# Работа с проектом

## Контракты агентов

- Сначала прочитайте `docs/agent-contracts.md` и вход/выход своего узла в
  `src/multi_agent_docs/agent_contracts.py`.
- В задачах улучшения промпта/качества сохраняйте имена полей, типы, сигнатуры,
  владельцев token_usage и договорённые входы/выходы.
- Не расширяйте общий State, API-модели, LLMClient или маршруты графа как
  сопутствующий рефакторинг. Контрактные изменения должны быть явно заявлены
  задачей и описаны вместе с совместимостью потребителей.
- Не обновляйте `contracts/v1.json`, не удаляйте runtime-guards и не ослабляйте
  контрактные тесты только ради зелёного CI. Для изменений интерфейса нужно
  явное обоснование и согласование с командой, а не автоматическое обновление.
- Для агента возвращайте только объявленный patch; технический token_usage
  является полной накопленной статистикой, а не дельтой. Не изменяйте чужой расход.
- Моки проверяют код и интерфейсы. Качество текста проверяйте реальной моделью
  на размеченных примерах, не выдавайте зелёные mock-тесты за доказательство качества.

## Проверки

Из корня проекта в активном окружении с dev-зависимостями:

```sh
python -m pytest tests/test_agent_contracts.py
python -m pytest
```

При изменении только своего агента сначала запускайте относящиеся к нему
проверки; перед завершением изменения выполняйте полный набор тестов.

## Git

- Работайте отдельной веткой от актуального main; сохраняйте посторонние
  незакоммиченные файлы пользователя.
- Используйте настроенную для этого проекта Git-идентичность пользователя.
- Не переписывайте общую историю и не выполняйте force-push без явной задачи.
- Не создавайте PR без прямой просьбы пользователя. Отправка и слияние изменений
  должны соответствовать явно согласованному объёму задачи.
