# Требования к backend MVP

## Назначение

Backend принимает PDF, TXT, DOCX, HTML, Markdown и CSV, выполняет мультиагентный анализ через LangGraph и GigaChat и сохраняет историю в SQLite.

## Основной сценарий

1. Клиент отправляет документ в `POST /analyze`.
2. Backend валидирует файл, создаёт запись и возвращает ID фоновой задачи.
3. Единственный worker выполняет анализ и сохраняет результат или безопасную ошибку.
4. Клиент получает статус и результат через `GET /documents/{id}`.

## Ограничения MVP

- PDF, UTF-8 TXT, DOCX, HTML (`.html`/`.htm`), UTF-8 Markdown (`.md`/`.markdown`) и UTF-8 CSV;
- из DOCX извлекаются основной текст и таблицы; распакованные данные ограничены 100 МБ;
- CSV принимает разделители запятая, точка с запятой, табуляция и `|`, сохраняет порядок строк и колонок;
- загрузка до 100 МБ;
- извлечённый текст до 250 000 токенов;
- один анализ одновременно;
- локальная очередь без Redis;
- исходные файлы после обработки не хранятся;
- нейрослоп является эвристической оценкой, а не достоверным детектором AI-текста;
- необязательный интерфейс Gradio работает поверх HTTP API, не запускает pipeline самостоятельно.

## Эксплуатационные требования

- изменения схемы оформляются Alembic-ревизиями;
- рабочий и mock-режимы запускаются одинаковым HTTP API;
- сквозные API-тесты не требуют ключа или сети;
- Makefile является основной точкой команд разработки;
- Postman-коллекция покрывает анализ, статус, историю, health и ошибки.
